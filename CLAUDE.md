## Architecture

This is a Next.js App Router project styled with Tailwind CSS v4 and shadcn/ui. Its one feature is an AI-generated dictionary: a search box (`components/dictionary-search.tsx`, rendered from `app/page.tsx`) calls `app/api/define/route.ts`, which returns a definition generated by Gemini Flash Lite, cached in Firestore.

**Next.js version is non-standard.** See `AGENTS.md` (imported above) — this is not the Next.js version in your training data. Check `node_modules/next/dist/docs/` for the real API before using App Router conventions you already "know" (routing, layouts, metadata, etc.). Note: `app/api/define/route.ts` deliberately uses the Web-standard `Request`/`Response` APIs rather than `NextRequest`/`NextResponse`, to sidestep any drift in Next-specific request typing in this version.

### AI dictionary feature

- **`lib/gemini.ts`** — the only module that talks to Gemini. Owns the `GoogleGenAI` client, the structured-output `responseSchema` (`{ found, word, message, entries: [{ partOfSpeech, definition, example }] }`), and `normalizeWord()`/`InvalidWordError` for input validation. Model id is `GEMINI_MODEL` env var, defaulting to a hardcoded id — Gemini's flash-lite model naming moves fast, so re-check https://ai.google.dev/gemini-api/docs/models if lookups start failing. `DefinitionEntry`'s `translations` field is the one exception — always `[]` straight out of this module; it's populated downstream by `lib/translate.ts`, not by Gemini.
- **`lib/translate.ts`** — the only module that talks to the Google Cloud Translation API. `translateEntries(word, entries)` batches all of a word's senses into one request per target language (`TRANSLATE_TARGET_LANGUAGES` env var, comma-separated ISO 639-1 codes, defaults to `vi`) rather than one request per sense. Input to the API is `"${word} - ${definition}"`; the translated string is split back into `word`/`meaning` on the first surviving dash separator. Never throws — a missing `GOOGLE_TRANSLATE_API_KEY` or a failed language just means no translations for that language, since this is an enhancement on top of the core lookup, not a requirement for it.
- **`lib/firebase-admin.ts`** — singleton Firebase Admin app + Firestore instance (guarded against Next dev hot-reload double-init via `getApps()[0]`). Explicitly resolves a project id from `GOOGLE_CLOUD_PROJECT`/`GCLOUD_PROJECT` for local dev (user ADC credentials don't carry one, unlike a service account); on Firebase App Hosting both credentials and project id are auto-provided at runtime and this resolution is skipped.
- **`lib/definitions-cache.ts`** — the read-through cache in front of Gemini (+ Translation). `getDefinition(rawWord, ip)` normalizes the word, checks the `definitions/{normalizedWord}` Firestore doc, and on a miss calls `lib/gemini.ts`, then `lib/translate.ts`'s `translateEntries()` (via `attachTranslations()`, itself never throwing), then writes the combined result back (a cache-write failure is logged, never surfaces to the caller). Both "found" and "not found" results are cached, so repeated gibberish isn't re-billed either. This is the only module that touches Firestore directly — `firestore.rules` denies all client read/write, since only the server-side Admin SDK ever reads this collection.
- **`app/api/define/route.ts`** — `GET ?word=` wrapping `getDefinition()`. 400 for empty/invalid input, 502 for upstream (Gemini/Firestore) failures.
- **`components/dictionary-search.tsx`** — Home's search box + Recent Lookups only; it doesn't render lookup results itself. Submitting a search or picking a recent word navigates to `/word/[word]` (`components/word-detail.tsx`), which owns the actual lookup and every one of its states (loading, found, not-found, error).
- **Env vars** (no `.env.example` exists in the repo — the harness blocks writes to any `.env*` path, so this list is the source of truth): `GEMINI_API_KEY`, `GEMINI_MODEL`, `GOOGLE_TRANSLATE_API_KEY` (optional), `TRANSLATE_TARGET_LANGUAGES` (optional), and for local dev either `GOOGLE_APPLICATION_CREDENTIALS` (service account JSON) or `gcloud auth application-default login` plus `GOOGLE_CLOUD_PROJECT`. See `README.md` for the full setup flow.
- **Firebase deployment config**: `apphosting.yaml` (App Hosting run config + env/secret bindings), `firebase.json` (App Hosting + Firestore config pointers), `.firebaserc` (project id, `lexi-gemini`), `firestore.rules` (deny-all client access), `firestore.indexes.json` (empty — all lookups are single-doc-by-ID). The backend (`lexi`) is connected to this repo on GitHub — pushing to `main` triggers an automatic build/rollout; `firebase deploy --only apphosting` is only needed for an out-of-band deploy. Secrets (`GEMINI_API_KEY`, `GOOGLE_TRANSLATE_API_KEY`) are separate from the GitHub-triggered build — see `README.md`'s Deploy section.

### UI component system (shadcn/ui)

- `components.json` drives everything: style `base-maia`, base color `mist`, Tailwind CSS v4 (`cssVariables: true`), icon library `lucide`. Path aliases: `@/components`, `@/components/ui`, `@/lib`, `@/hooks` (all resolve via the single `@/*` tsconfig path).
- **Primitive library is Base UI (`@base-ui/react`), not Radix.** Existing shadcn/Radix knowledge for prop APIs (`asChild` vs `render`, event handling, etc.) doesn't directly transfer — check `.agents/skills/shadcn/rules/base-vs-radix.md` before assuming an API.
- Theme tokens (colors, radius, sidebar/chart colors) are CSS variables defined in `app/globals.css` under `:root` / `.dark`, remapped into Tailwind via the `@theme inline` block. `--radius` is the single source for all corner-radius scale steps (`--radius-sm` … `--radius-4xl` are derived from it). Edit `app/globals.css` for any theme/token change — never hand-roll a second config file.
- Installed components: `button`, `field`, `input`, `input-group`, `skeleton`, `empty`, `badge`, `card`, `alert`, `spinner`, `label`, `separator`, `textarea`. Use the shadcn CLI (`npx shadcn@latest add <component>`) to add more rather than hand-writing primitives; the project's shadcn skill (`.agents/skills/shadcn/`) has the full ruleset (forms use `FieldGroup`/`Field`, semantic color tokens only, `gap-*` not `space-y-*`, icons via `data-icon`, etc.) — follow it for any UI work.
- `lib/utils.ts` exports `cn()` (`clsx` + `tailwind-merge`) — the standard way to compose/override Tailwind classes across this codebase.

### Fonts

`app/layout.tsx` loads four `next/font/google` fonts (Geist, Geist Mono, Figtree as `--font-sans`, Outfit as `--font-heading`) and applies them as CSS variables on `<html>` via `cn()`. `globals.css` maps `--font-sans`/`--font-mono`/`--font-heading` into Tailwind's theme, so use the `font-sans`/`font-mono`/`font-heading` utility classes rather than referencing font variables directly.
